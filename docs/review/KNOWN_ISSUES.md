# 已知问题清单

这份清单故意写得偏“挑问题”，方便外部审查时直接对焦，不做粉饰。

## 1. section 切分仍有边界风险

### 当前状态

目前系统已经通过“只认 10 个正式一级标题”大幅降低了串栏概率，板块页也改成了严格按 `section_key` 取数。

### 仍然存在的风险

- 如果真实底稿的一级标题被改写得太多，可能导致 section 识别失败
- 如果一级标题缺失，后续 section 边界仍可能整体偏移
- 如果一级标题被放进异常 Word 结构中，当前解析器未必能识别

### 结论

section 串栏风险已经从“高”降到“中低”，但并没有达到“可以完全不担心”的程度。

## 2. 表格解析仍可能不稳定

### 已做的事情

- 已按 docx 顺序读取表格
- 已保留表头和行列关系
- 已在页面中输出 HTML table

### 仍然存在的问题

- 复杂合并单元格不一定能完整还原
- 嵌套表格没有专门处理
- 某些多行表头可能被误当成普通行
- Word 表格的样式、颜色、边框不会原样继承

### 结论

当前表格处理适合“内容展示”，不适合“版式级还原”。

## 3. 某些板块仍可能在极端样本下重新串栏

### 当前状态

- 页面层已经严格绑定 section key
- 空 section 不再自动 fallback 到别的 section

### 仍然存在的问题

真正的风险点已经从“页面取错数据”转移到了“解析器本身切错 section”。

也就是说：

- 页面层现在基本不串栏
- 但如果解析层把正文切错，页面仍会忠实地显示“错误的 section 内容”

### 结论

下一步真正该继续打磨的是解析器，而不是模板层。

## 4. 页面渲染仍有层级与产品化问题

当前页面已经明显比早期版本好，但仍有下面的问题：

- 顶部操作按钮较多，仍带有内部工具感
- 调试入口还暴露在主界面
- 某些板块页很长，阅读压力仍不小
- 卡片和表格混排时，部分页面会显得信息密度过高
- 历史页虽然清楚，但还不够像正式归档中心

## 5. PDF 导出是结构化导出，不是网页打印

### 这一点的好处

- 不是简单浏览器打印网页
- 内容结构更可控
- 能输出封面、简报、板块、表格

### 这一点的不足

- 样式和网页不是一模一样
- 卡片视觉在 PDF 中是简化版
- 表格分页效果取决于 ReportLab，不等同网页阅读体验
- 超长内容会让 PDF 页数偏多

### 结论

当前 PDF 更像“结构化展示稿”，不是“网页外观复刻版”。

## 6. 历史记录机制可用，但不够稳健

### 当前状态

- 每次上传都保存原始文件
- 每次上传都归档解析 JSON
- 数据库存当前版本和历史版本

### 主要问题

- 重复上传会不断累积文件和 JSON
- 没有清理策略
- 没有版本差异浏览界面
- 没有“撤回本次上传”能力

### 迁移问题

数据库里保存的是绝对路径。

这意味着复制到另一台电脑后：

- 页面里显示的旧路径会失真
- 但数据库中的正文仍能继续显示

## 7. 新增 / 更新 / 历史保留 判断不算强可靠

当前状态判断主要依赖：

- 归一化文本
- `SequenceMatcher`
- 文本包含关系
- 若干阈值

这类判断方法的局限是：

- 不懂业务语义
- 对结构调整敏感
- 对表格改写较敏感
- 可能把“表达改写但信息相同”的内容错判成更新或新增

### 特别注意

为了避免串栏，当前版本已经取消“跨板块回填正文”。

因此会出现一种体验问题：

- 状态是“历史保留”
- 但正文页未必展示最近有效正文
- 只显示提示信息

这是当前版本中需要外部审查重点讨论的问题。

## 8. UI 仍有不够“老板友好”的地方

当前 UI 的问题主要不是难看，而是还不够成熟：

- 首页已可看，但仍偏“系统页”而非“汇报页”
- 调试入口不应长期暴露给老板
- 某些板块页内容过长时缺少折叠和摘要
- 历史页缺少更强的筛选和排序能力
- 没有“只看今日重点变化”的纯老板模式

## 9. 自动化测试缺失

目前项目主要靠人工自测，没有正式测试文件。

缺失的测试包括：

- section 切分单元测试
- 表格解析回归测试
- 状态判断测试
- PDF 导出结果测试
- 历史迁移测试

这会让后续功能升级时更容易引入回归问题。

## 10. 架构层面的隐患

### `services.py` 过重

当前 `app/services.py` 既做业务流程，也做页面取数，也做 PDF 数据准备。

风险：

- 后续维护成本继续上升
- 审查难度高
- 改一处容易影响多处

### 模板与数据结构耦合较深

`rendering.py` 输出的结构与模板使用方式绑定很紧。

风险：

- 后续如果换模板版式，改动面会较大

## 11. 当前最值得优先解决的问题排序

建议外部审查者按下面顺序看：

1. section 解析鲁棒性
2. 状态语义与页面展示的一致性
3. 数据库绝对路径导致的迁移问题
4. `services.py` 过重
5. 表格复杂样本稳定性
6. PDF 对外展示质量
