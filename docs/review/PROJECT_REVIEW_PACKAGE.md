# 项目总说明

## 1. 项目名称

沉香行业情报浏览系统_1.0

## 2. 项目目标

这是一个本地运行、本地保存、浏览器打开的情报浏览系统。

它的目标不是自动抓取互联网，也不是自动写稿，而是把两类人工整理后的输入文件接入本地系统，完成：

- 文件上传
- 文件类型识别
- 文本解析
- 研究底稿 10 个正式板块切分
- 板块化展示
- 历史归档
- 当日 PDF 展示成果导出

系统当前面向的真实使用场景是：

1. 研究底稿由外部工具生成
2. 每日简报由 ChatGPT 或其他工具生成
3. 用户把这两份文件上传到本地网页系统
4. 老板在浏览器里先看简报，再看板块，再看历史

## 3. 当前版本说明

- 版本定位：本地版 1.0
- 技术栈：Flask + Jinja2 + SQLite + python-docx + pypdf + ReportLab
- 运行方式：Windows 本地 Python 环境，浏览器访问 `http://127.0.0.1:5050`
- 数据存储方式：
  - 原始文件：`uploads/originals/`
  - 解析结果：`archive/parsed/`
  - 数据库：`database/intelligence_browser.db`
  - 导出成果：`exports/pdf/`
- 当前审查快照日期：2026-04-03

## 4. 核心功能列表

### 文件接入

- 上传研究底稿
- 上传每日分析简报
- 支持拖拽上传和点击上传
- 根据文件名和正文内容识别文档类型
- 支持 `.docx`、`.md`、`.txt`、`.pdf`

### 解析与结构化

- 顺序读取 docx 正文段落
- 顺序读取 docx 表格
- 将研究底稿按 10 个正式一级板块切分
- 将小节标题识别为板块内部层级
- 保留段落、换行、表格内容
- 输出板块渲染模型

### 页面展示

- 首页优先展示《每日分析简报》
- 首页展示板块总览与状态标签
- 板块详情页展示正文、卡片、表格
- 左侧导航固定并可滚动
- 历史记录页按日期回看
- section 调试页查看板块边界和预览

### 数据与归档

- 原始文件本地保存
- 解析结果 JSON 本地保存
- SQLite 保存文档与板块快照
- 同一日期、同一类型保留“当前版本”标记

### 导出

- 导出“系统整理后的展示结果”PDF
- PDF 包含封面、简报、10 个板块
- 导出按钮在首页、历史页、板块页都可见

## 7. 当前已知问题

以下问题在当前版本中仍需诚实保留：

- section 一级标题识别仍依赖固定标题与别名；如果源 docx 的标题写法偏差很大，切分仍有失败风险。
- 表格解析优先保证内容完整，不保证 Word 的复杂表格样式一比一还原。
- “新增 / 更新 / 历史保留”是启发式文本比对，不是业务语义级判断。
- 历史记录会不断累积重复上传版本，目前没有清理机制。
- 数据库存了绝对路径；项目复制到另一台电脑后，旧历史记录的路径展示会指向原电脑。
- PDF 导出是结构化生成，不是网页像素级还原。
- 页面已经能看，但整体仍更像内部工具，而不是完全成熟的老板汇报系统。

## 8. 当前最影响使用体验的 bug / 风险

当前最值得优先关注的不是样式，而是下面两个结构性风险：

### 风险一：非标准标题下的 section 切分风险

当前 section 切分已经比前一版稳定很多，但仍然依赖正式一级标题。

如果未来上传的底稿出现以下情况，仍可能重新引发串栏或空板块：

- 一级标题名称改写过多
- 一级标题前后装饰字符太多
- 标题被放进异常表格/文本框
- 本应存在的一级标题缺失

### 风险二：历史状态语义与页面展示存在轻微张力

为了彻底避免“空板块串到别的板块”，当前详情页不再直接拿别的 section 内容回填。

这带来的副作用是：

- 某些板块可能被判为“历史保留”
- 但当天页面仍只显示“未解析出有效正文”的提示
- 用户会感觉状态标签和正文展示之间存在语义落差

## 9. 后续建议优化方向

### 第一优先级

- 给 section 切分增加更多真实样本测试
- 降低标题写法变化带来的切分风险
- 明确“历史保留”页面到底显示当天空提示，还是显示最近有效内容的受控只读副本
- 解决数据库绝对路径对迁移的影响

### 第二优先级

- 拆分 `services.py`，降低单文件职责过重的问题
- 为解析器、状态判断、PDF 导出增加自动化测试
- 给历史记录增加版本清理与版本对比

### 第三优先级

- 进一步收紧老板视角的阅读体验
- 减少调试入口在主界面中的存在感
- 优化 PDF 的章节分页、表格分页和封面样式

## 10. 交给外部审查者时的建议

如果把这个项目交给另一个 GPT 或研究模型独立审查，建议重点让它看：

- `app/parsers.py`
- `app/services.py`
- `app/rendering.py`
- `app/pdf_export.py`
- `app/routes.py`
- `app/templates/section_detail.html`
- `app/static/css/style.css`

并重点让它回答：

1. section 切分是否足够稳
2. 页面是否严格绑定正确 section
3. 表格解析是否足够可靠
4. 历史记录与状态判断是否合理
5. 迁移到另一台电脑是否足够稳
6. PDF 导出是否足够适合对外展示
