# 闻脉台隐形 bug 检测报告 2026-04-21

## 本轮目标

本轮只做工程收口型排查：

1. 首页与关键页面隐形交互 bug
2. 路径 / 下载 / 导出 / 回跳边界
3. CSS / JS 叠加风险
4. 最值钱的一小组测试
5. 最小必要修复

本轮没有扩新功能，没有改 parser / rebuild 主逻辑，也没有进入正式云部署。

## 本轮已修问题

### 1. 下载 / 导出路径缺少受控根目录约束

问题：

- 文档下载与导出下载此前基本依赖数据库中的 `stored_path`
- 如果数据库值异常，理论上可能把 `send_file()` 指到受控目录之外

处理：

- 新增统一路径守卫，要求下载路径必须落在允许根目录内
- 文档下载只允许命中 `FILE_LIBRARY_ROOT`
- 导出下载只允许命中 `EXPORTS_ROOT`
- 路径为空、越界、文件不存在或不是文件，都会被拒绝

结果：

- 下载入口不再直接信任数据库里的路径字符串
- 未来上云后，异常 `stored_path` 不会直接穿透到下载层

### 2. 首页 Hero 仍受旧样式宽度限制

问题：

- 首页欢迎标题虽然已经改成单行思路
- 但旧样式里仍有 `.welcome-hero-reading .welcome-copy h3 { max-width: 12ch; }`
- 这会继续限制标题宽度，长姓名场景下容易出现压缩、挤压或视觉不稳定

处理：

- 在首页专用规则里把欢迎标题改成真正的单行弹性布局
- 去掉首页场景下对标题的窄宽度继承影响
- 给姓名块补 `min-width: 0 + overflow hidden + ellipsis`

结果：

- 正常桌面宽度下继续保持单行
- 极长 `display_name` 不会把布局顶坏
- 不需要重新开一轮 Hero 设计

## 本轮确认但暂不改的问题

### 1. `style.css` 与 `collaboration.css` 仍有重复覆盖

已确认存在重复定义的区域：

- `.nav-link.active`
- `.hero-subtitle`
- `.primary-button`

当前判断：

- 这不是立即阻断级 bug
- 但确实存在“样式覆盖关系依赖加载顺序”的耦合风险

本轮不动原因：

- 现在强行抽离会变成一轮样式系统重构
- 不符合“最小必要修复”范围

建议：

- 后续若再做前台维护，优先把“基础样式”和“协作增强样式”拆清

### 2. scrollspy 仍依赖固定 section id

已确认：

- `main.js` 的首页 scrollspy 依赖固定 section id：
  - `today-focus`
  - `today-new`
  - `recent-versions`
  - `history-archive`

当前判断：

- 这种依赖本身不算错误
- 但如果未来有人改模板锚点、改导航 href、改 hash map，而没有同步 JS，就会静默失效

本轮处理：

- 补了锚点完整性测试

本轮不继续重写原因：

- 当前逻辑已经够用
- 真正的大改会超出这轮边界
