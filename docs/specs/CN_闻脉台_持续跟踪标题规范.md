# 闻脉台持续跟踪标题规范

本文档用于约束“同一事件持续跟踪时，标题尽量保持稳定”。当前上传契约没有新增 `event_anchor / canonical_title` 列，因此标题稳定性本身就是上游契约的一部分。

## 1. 目标

目标不是把标题写得更华丽，而是让同一事件在跨天、跨版跟踪时不因为说法变化而被误拆成新事件，或误并到别的事件上。

## 2. 基本规则

### 1. 同一事件，标题尽量不变

如果只是新增了时间、规格、渠道、合作对象、价格、官方口径等事实，标题原则上保持不变。

### 2. 标题只保留稳定骨架

优先使用：

- 对象
- 动作
- 必要限定词

不建议反复加入：

- 重磅
- 最新
- 值得关注
- 进一步
- 持续发酵
- 引发热议

### 3. 先命名事件，再写内容

标题负责标识“这是什么事件”，`核心内容` 和 `delta_text` 负责表达“这次新增了什么”。

### 4. 不要把新增事实挤进标题

新增事实应优先进入：

- `核心内容`
- `本次新增事实`

不要每次把新事实都改写进标题，导致标题骨架不停漂移。

## 3. 推荐标题结构

推荐使用以下结构之一：

- `{对象}发布{动作}`
- `{对象}上线{产品或渠道}`
- `{对象}公布{政策/计划/合作}`
- `{对象}更新{项目或系列}`

示例：

- `观夏上线空间香氛礼盒`
- `闻献发布联名系列`
- `海南发布沉香产业扶持政策`
- `观夏开设线下快闪空间`

## 4. 正确示例

同一事件第一天：

- 标题：`观夏上线空间香氛礼盒`
- 核心内容：`观夏发布空间香氛礼盒，并公布上线时间。`
- 本次新增事实：`新增上线时间。`

同一事件第二天新增规格信息时：

- 标题：`观夏上线空间香氛礼盒`
- 核心内容：`观夏补充公布礼盒规格与定价。`
- 本次新增事实：`新增礼盒规格和定价。`

这属于正确跟踪，因为标题稳定，新增事实进入正文和 `delta_text`。

## 5. 错误示例

同一事件第一天：

- `观夏上线空间香氛礼盒`

同一事件第二天却改成：

- `观夏重磅发布更值得关注的空间香氛新品动作`

同一事件第三天又改成：

- `观夏空间香氛新品进一步发酵并引发关注`

这属于错误写法，因为：

- 标题骨架频繁漂移
- 混入评价词和总结词
- 下游更容易把它判成不同事件

## 6. 何时允许改标题

只有在以下情况之一成立时，才建议新起标题：

- 事件对象变了
- 事件动作本身变了
- 原本是一个新品发布，后来变成另一个独立合作或政策事件
- 原标题本身命名错误，需要一次性修正为稳定版本

如果只是事实补充，不建议改标题。

## 7. 执行口诀

- 同一事件，不改骨架
- 新增事实，写进正文
- 少写修辞，多写对象
- 标题识别事件，`delta_text` 表达新增
