## 6. fail-closed 守卫已经做了什么

当前 `create_app()` 已经进入“本地宽松、production / rehearsal 严格拒绝启动”的模式。

production / rehearsal 场景下，以下情况会直接拒绝启动：

1. 没有真实配置来源
2. 没有显式 runtime 路径配置
3. 关键运行目录不存在
4. `DATABASE_PATH` 缺失或不是有效文件
5. 数据库缺少核心业务表
6. 数据库呈现明显壳库特征
7. `RAW_DATA_ROOT / FILE_LIBRARY_ROOT / ARCHIVE_ROOT` 与数据库状态明显不匹配
8. `SQLite + workers > 1`

同时，production 模式下已经不再允许靠默认路径自动创建壳 runtime，也不再在启动阶段默认执行文档升级修复链路。

## 11. PUBLIC_BASE_URL 与 TRUST_PROXY_HEADERS 接法

### PUBLIC_BASE_URL

- 本地可为空
- 服务器演练时应显式设置为外部访问 origin
- 只允许 origin，不带 path / query / fragment

示例：

- `https://intel.example.com`

### TRUST_PROXY_HEADERS

- 默认保持 `false`
- 只有当应用明确运行在自有、可信的反向代理之后，才允许开启
- 开启后才会信任 `X-Forwarded-*`
