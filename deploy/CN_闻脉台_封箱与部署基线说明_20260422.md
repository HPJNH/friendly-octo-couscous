# 闻脉台封箱与部署基线说明

## 1. 当前阶段
- 当前版本已进入封箱前最终基线阶段
- 当前重点不是继续开发，而是保证目录干净、文档清楚、部署边界明确、发布基线可冻结
- 当前可进入第三方“仅部署、仅试跑、仅验证”阶段，但不等于已完成正式公网生产化

## 2. 当前最终保留的程序本体目录
- `app/`
- `config/`
- `deploy/`
- `docs/`
- `scripts/`
- `tests/`

## 4. 已归档的历史材料
当前不再混入程序主目录视角的历史材料，统一保留在 `archive/` 下。

主要归档区包括：
- `archive/review_history/`
- `archive/research_history/`
- `archive/legacy_exports/`
- `archive/pdf_exports/`

这类材料包括：
- 历史代码审阅包
- 历史状态说明
- 历史 QA 截图
- 旧研究材料
- 旧导出物与旧说明草稿

## 5. 已隔离的本地私密材料
当前本地私密材料统一隔离至：

- `archive/private_local_only/`

其中包括：
- 真实 `local_settings.json`
- 真实数据库副本与数据库备份
- 真实底稿、linked 底稿、review / verification 数据
- 真实文件库、日志、应急恢复材料
- 真实 PDF / 报告导出物
- 含敏感上下文的审阅包

补充说明：
- 当前运行期数据库文件若仍驻留在运行目录，仅视为本地运行残留，不属于部署交付内容
- 第三方部署方不得接触这些私密本地材料

## 6. 当前架构边界
- 当前默认数据库为 SQLite
- 当前只支持单实例
- 当前不建议多 worker 并发写入
- 当前未接 MySQL / Redis / 对象存储
- 当前未完成正式 Nginx / HTTPS / 多实例生产化接线

因此，当前更适合：
- 部署试跑
- 目录和持久卷验证
- 配置校验
- 脱敏数据联调

当前不适合直接视为：
- 高并发生产架构
- 多实例弹性扩展架构

## 7. 当前目录收口结论
当前项目主目录已经从“长期研究仓库”收口到“可部署程序仓库”的状态：

- 程序本体清晰
- 部署说明完整
- 私密材料已隔离
- 历史材料已归档
- 当前目录可以交给第三方执行仅部署工作

## 8. 当前发布基线说明
- 当前发布基线以本轮最终封箱提交为准
- 具体分支名与 commit hash 以本轮 GitHub 冻结输出为准
- 本说明文件本身属于最终部署基线的一部分

## 9. 当前是否适合进入正式部署
结论：

- 适合进入“单实例、先试跑、先验证”的正式部署准备阶段
- 仍不建议直接带真实敏感数据做首次第三方部署

建议顺序：
1. 用当前程序本体与配置模板完成部署试跑
2. 验证启动、路径、持久卷、日志、访问控制
3. 再决定是否导入脱敏数据或切换到自有服务器环境
