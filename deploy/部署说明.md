# 部署说明

## 当前阶段定位

本轮完成的是“反向代理前的服务进程与云部署准备包”。目标不是立刻上阿里云、不是立刻接 Nginx / HTTPS，而是把闻脉台收口到可以照着试跑单实例云端的程度。

当前仍然不是：

- 正式公网部署成品
- 多实例可扩展版本
- MySQL / Redis 版本
- 对象存储版本

## 两个启动入口

### 1. 本地入口

- `python run.py`

用途：

- `local` 模式
- 桌面调试
- 局域网试用

特点：

- 会输出本机 / 局域网访问提示
- 会自动打开浏览器

### 2. 服务器入口

- `wsgi.py`

用途：

- 单实例服务进程运行
- 单容器运行
- 后续接反向代理前的标准接线入口

特点：

- 只暴露 `app` / `application`
- 不包含本地浏览器逻辑
- 推荐统一通过 `wsgi:app` 启动

## 当前推荐部署姿态

当前版本推荐姿态已经明确为：

1. 单实例
2. 持久卷
3. SQLite 默认数据库

当前不建议：

- 多实例
- 多 worker 并发写
- 水平扩容

## 运行根路径

当前已经统一出运行根：

- `APP_RUNTIME_ROOT`

如果不配置，默认使用项目目录；如果配置了该值，所有相对运行路径都会落到这个根目录下。

建议在服务器或容器里这样理解：

- 程序代码目录：只放代码本体
- 运行根目录：挂持久卷

## 当前关键运行目录

当前关键目录已经收口为：

- `DATA_ROOT`
- `STORAGE_ROOT`
- `EXPORTS_ROOT`
- `ARCHIVE_ROOT`

当前运行期还会继续派生这些叶子路径：

- `DATABASE_PATH`
- `TEMP_UPLOAD_ROOT`
- `FILE_LIBRARY_ROOT`
- `EXPORT_ROOT`
- `REPORT_EXPORT_ROOT`
- `RAW_DATA_ROOT`
- `REVIEW_DATA_ROOT`
- `VERIFICATION_DATA_ROOT`
- `LINKED_DATA_ROOT`
- `LOG_ROOT`

## 当前建议持久化的目录

建议持久化：

- `DATA_ROOT`
- `STORAGE_ROOT`
- `EXPORTS_ROOT`
- `ARCHIVE_ROOT`

补充说明：

- 项目根目录的 `archive/` 仍然是历史材料归档区，不建议和运行时 archive 混用
- 当前运行时 `ARCHIVE_ROOT` 默认仍落在 `data/processed/archive_parsed/`

## 启动时目录守卫

应用启动时会自动执行：

1. 目录初始化
2. 关键目录可写性检查

当前重点检查：

- `DATA_ROOT`
- `STORAGE_ROOT`
- `EXPORTS_ROOT`
- `ARCHIVE_ROOT`
- 数据库父目录

如果关键目录不存在，会自动创建；如果关键目录不可写，会直接拒绝启动并抛出清晰错误。

## SQLite 单实例边界

当前默认数据库仍是 SQLite，因此必须写死以下边界：

- `SINGLE_INSTANCE_ONLY=true`
- 若数据库仍为 SQLite，则 `APP_SERVER_WORKERS` / `WEB_CONCURRENCY` 只能为 `1`
- `production` 模式下如果显式配置大于 `1`，程序会直接拒绝启动

这不是建议，而是当前版本的运行边界。

## 推荐的单实例服务进程方式

推荐使用单实例 WSGI 运行方式，例如：

```bash
waitress-serve --listen=0.0.0.0:5050 wsgi:app
```

注意：

- 不要继续依赖 `run.py`
- 不要把 worker 配成大于 `1`
- 不要跳过 `production` 配置守卫
- 如果未来改用支持 worker 的 WSGI 服务器，仍然只允许 `1` 个 worker

## PUBLIC_BASE_URL 与未来代理语义

本轮把 `PUBLIC_BASE_URL` 正式纳入了准备层：

- 本地可留空
- 如果已有公网域名或未来准备走反向代理，应明确配置为完整外部基础地址
- 示例：`https://intel.example.com`
- 不要包含 path、query、fragment

当前它已经开始影响：

- 登录回跳的合法来源判断
- 管理入口回跳的合法来源判断
- 页面 `next` / 回跳链路的域名与协议认知

也就是说，程序不再只按 `localhost` 思维判断“自己人”，而是开始接受：

- 当前请求同源地址
- 配置中的 `PUBLIC_BASE_URL`

同时继续拒绝陌生外域跳转。

## TRUST_PROXY_HEADERS

如果未来接入反向代理，本轮还预留了最小、可控的代理头开关：

- `TRUST_PROXY_HEADERS`
- `PROXY_FIX_X_FOR`
- `PROXY_FIX_X_PROTO`
- `PROXY_FIX_X_HOST`
- `PROXY_FIX_X_PORT`
- `PROXY_FIX_X_PREFIX`

当前默认关闭。只有在应用明确运行在“你自己可控的可信反向代理”后面时，才应显式打开。不要无脑信任所有代理头。

## 日志建议

当前建议：

- 日志写入 `LOG_ROOT`
- `LOG_ROOT` 默认放在 `STORAGE_ROOT/logs`
- 日志目录应挂在持久卷上，不建议跟随临时容器目录一起丢失
- 如后续接入进程管理器或反向代理，可把标准输出日志交给外层系统统一收集，但运行目录中的日志仍建议保留一份短周期可追溯记录

## 备份建议

至少应覆盖：

- `DATABASE_PATH`
- `STORAGE_ROOT`
- `EXPORTS_ROOT`（按业务需要）
- `ARCHIVE_ROOT`（按业务需要）

建议原则：

- SQLite 数据库至少每日备份一次
- 每次大批上传、重建前或版本升级前额外做一次快照
- 如果文件库承载业务原件，`STORAGE_ROOT` 应与数据库同周期备份
- `EXPORTS_ROOT` 和 `ARCHIVE_ROOT` 可按追溯需要采用每日或每周备份

## production 模式仍必须满足的配置

production 启动前必须准备：

- `APP_ENV=production`
- 真实 `SECRET_KEY`
- `SESSION_COOKIE_SECURE=true`
- `BOOTSTRAP_ADMIN_ENABLED=false`
- 已替换的管理员口令 / 初始访问码
- `HIDE_INTERNAL_PATHS=true`
- 真实配置来源
- `APP_SERVER_WORKERS=1`

## 当前还没做的事

完成这一轮后，项目已经具备“单实例服务进程 + 反向代理前准备”的条件，但还没有进入：

- 正式公网部署
- HTTPS 真证书接入
- Nginx 真配置
- MySQL / Redis
- 对象存储
- 多实例方案
